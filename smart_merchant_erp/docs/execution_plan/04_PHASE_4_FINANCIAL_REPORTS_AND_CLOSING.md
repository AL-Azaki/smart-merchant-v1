## 2. محرك التقارير المالية المعتمد (Reports Engine Architecture)

جميع التقارير تعتمد على الاستعلام المباشر من جداول الـ Drift عبر `AccountingDao` و `SalesDao` و `PurchasingDao`:

```

└───────────────────────────────────┬────────────────────────────────────┘

         ┌──────────────────────────┼──────────────────────────┐
         │                          │                          │
┌────────▼─────────┐       ┌────────▼─────────┐       ┌────────▼─────────┐
│ 1. كشف الحساب    │       │ 2. ميزان المراجعة │       │ 3. الأرباح والخسائر│

├──────────────────┤       ├──────────────────┤       ├──────────────────┤
```

## 3. الخطوات التنفيذية التفصيلية (Implementation Steps)

### الخطوة 4.1: بناء محرك كشف الحساب التراكمي (Statement of Account Engine)
* مسار الملف: `lib/modules/reports/application/services/account_statement_service.dart`
* **المنطق الحسابي:**
  1. استقبال: `accountId` (أو `partyId`), `startDate`, `endDate`.
  2. **حساب الرصيد السابق (Opening Balance):**
     $$\text{Opening Balance} = \sum (\text{Debit} - \text{Credit}) \quad \forall \text{ date} < \text{startDate}$$
  3. **جلب حركات الفترة مرتبة زمنياً تصاعدياً (`ASC`):**
     * رقم الحركة، التاريخ، نوع المستند (فاتورة بيع، فاتورة شراء، سند قبض، سند صرف، قيد يدوي)، البيان، المدين، الدائن.
  4. **حساب الرصيد التراكمي (Running Balance):**
     $$\text{Running Balance}_i = \text{Running Balance}_{i-1} + \text{Debit}_i - \text{Credit}_i$$
  5. إرجاع النتائج لواجهة العرض ومحرر الـ PDF لطباعتها فوراً.

### الخطوة 4.2: محرك ميزان المراجعة (Trial Balance Engine)
* مسار الملف: `lib/modules/reports/application/services/trial_balance_service.dart`
* **المطلوب:**
  * استعلام يجمع كل الحسابات الفرعية النشطة من جدول `journal_entry_lines`:
    * كود الحساب، اسم الحساب، نوع الحساب.
    * إجمالي الحركات المدينة (`Total Debit`).
    * إجمالي الحركات الدائنة (`Total Credit`).
    * الرصيد الصافي: إذا كان مديناً يوضع في خانة "رصيد مدين"، وإذا كان دائناً يوضع في خانة "رصيد دائن".
  * **التحقق الذهبي في أسفل التقرير:**
    * `SUM(Total Debit) == SUM(Total Credit)`
    * `SUM(Net Debit Balances) == SUM(Net Credit Balances)`

### الخطوة 4.3: محرك قائمة الدخل والأرباح والخسائر (Income Statement / P&L)
* مسار الملف: `lib/modules/reports/application/services/profit_loss_service.dart`
* **المعادلة المعتمدة:**
  1. **صافي المبيعات (Net Revenue):**
     $$\text{Net Sales} = \text{إيراد المبيعات (حساب 41)} - \text{مردودات المبيعات}$$
  2. **تكلفة البضاعة المباعة (COGS):**
     $$\text{COGS} = \text{رصيد حساب تكلفة المبيعات (حساب 51)}$$
  3. **مجمل الربح (Gross Profit):**
     $$\text{Gross Profit} = \text{Net Sales} - \text{COGS}$$
  4. **المصروفات التشغيلية (Operating Expenses):**
     $$\text{Expenses} = \sum \text{حسابات المصروفات (إيجارات + رواتب + كهرباء + عجز جرد + غيرها)}$$
  5. **صافي الربح أو الخسارة (Net Operating Profit):**
     $$\text{Net Profit} = \text{Gross Profit} - \text{Expenses}$$

### الخطوة 4.4: محرك تقرير تقييم المخزون الحقيقي (Inventory Valuation Report)
* استخراج بيانات جدول `inventories` الحقيقية:
  * اسم الصنف، الباركود، المخزن، الكمية المتوفرة بالوحدة الأساسية.
  * متوسط التكلفة بالعملة الأساسية (`average_cost`).
  * إجمالي القيمة = $\text{الكمية} \times \text{average\_cost}$.
  * مطابقة إجمالي قيمة المخزون مع رصيد حساب "بضاعة المخزن" في دفتر الأستاذ العام.

### الخطوة 4.5: آلية قفل الفترات والإقفال السنوي (Lock Date & Year-End Close)
1. **تاريخ قفل الحركات (Transaction Lock Date):**
   * حقل في إعدادات النظام `system_settings.lock_date`.
   * قبل حفظ أي فاتورة، مرتجع، سند، أو قيد:
     ```dart
     if (entryDate.isBefore(lockDate)) {
       return Left(PeriodLockedFailure('لا يمكن إضافة أو تعديل حركات في فترة محاسبية مغلقة قبل $lockDate'));
     }
     ```
2. **دالة الإقفال السنوي (Year-End Close Use Case):**
   * عند انتهاء السنة المالية:
     1. احتساب صافي أرباح/خسائر السنة.
     2. إنشاء قيد إقفال آلي:
        * جعل جميع حسابات الإيرادات (مدينة) بأرصدتها لتصفيرها.
        * جعل جميع حسابات المصروفات (دائنة) بأرصدتها لتصفيرها.
        * ترحيل الفرق إلى حساب **"الأرباح المحتجزة / المرحلة (Retained Earnings - حساب 32)"**.
     3. تصفير حسابات النتيجة (الإيرادات والمصروفات) لبدء السنة الجديدة من الصفر.
     4. تدوير أرصدة الميزانية (الأصول، الخصوم، رأس المال) كأرصدة افتتاحية للسنة الجديدة.
     5. تحديث تاريخ القفل `lock_date` ليكون تاريخ نهاية السنة المقفلة لمنع أي تلاعب لاحق.

## 4. معايير القبول الصارمة (Acceptance Criteria)

- [ ] **AC-4.1:** كشف حساب العميل يظهر كل فاتورة وسند بالتاريخ ورقم المستند، مع رصيد تراكمي دقيق 100% يطابق الفواتير المتبقية.
- [ ] **AC-4.2:** ميزان المراجعة متزن دائماً: مجموع الأعمدة المدينة يساوي مجموع الأعمدة الدائنة بدون فارق حتى هللة واحدة.
- [ ] **AC-4.3:** قائمة الدخل تظهر صافي الأرباح محسوباً بدقة: (المبيعات - تكلفة البضاعة المباعة - المصروفات المسجلة بسندات الصرف).
- [ ] **AC-4.4:** محاولة تسجيل فاتورة أو سند بتاريخ أقدم من تاريخ القفل `lock_date` تُرفض فوراً وتظهر رسالة خطأ واضحة تمنع العملية.
- [ ] **AC-4.5:** تنفيذ الإقفال السنوي يصفر حسابات الإيرادات والمصروفات بالكامل ويرحل صافي الربح إلى حقوق الملكية بنجاح دون أي خطأ.

## 5. محاذير الخطر وقواعد الرفض (Danger Traps & Rejection Rules)

> [!CAUTION]
> **ممنوع قطعي (CRITICAL REJECTION):**
> 1. ممنوع حساب الأرباح في قائمة الدخل بناءً على أسعار بيع البضاعة فقط دون خصم تكلفة البضاعة المباعة COGS المستخرجة من متوسط التكلفة.
> 2. ممنوع السماح للمستخدم بتغيير تاريخ القفل إلى الوراء إلا بصلاحية مدير النظام العليا (Admin Master Password).
> 3. ممنوع تنفيذ الإقفال السنوي إذا كان هناك قيود يومية معلقة بحالة "مسودة" (Draft) دون ترحيلها أو حذفها.
